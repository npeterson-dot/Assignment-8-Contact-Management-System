For this assignment, I created a contact management system using a hash table to store and retrieve names and phone numbers. A hash table works well for this type of system because it allows the program to find information quickly without having to search through every contact individually. Instead, the hash function takes the contact's name and calculates an index where the information can be stored and found later. This makes the process much more efficient, especially when dealing with a large number of contacts.
One challenge with hash tables is handling collisions, which happen when two different names are assigned to the same index. To solve this problem, I used separate chaining with linked lists. Each index can hold multiple contacts through connected nodes, allowing the program to store both contacts without losing any information. I also made sure that inserting an existing name updates the phone number instead of creating a duplicate contact.
An engineer might choose a hash table over a list or tree when fast searches and updates are more important than keeping information in a specific order. Lists can be useful for organizing information sequentially, while trees are helpful when relationships or ordering matter. However, for a contact management system where users need to quickly find someone by name, a hash table is a practical choice.
This assignment helped me understand how hashing and linked lists can work together to make a system more efficient.
